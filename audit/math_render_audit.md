# Markdown 中 LaTeX 的渲染审计（2026-08-04）

## 起因

本仓库首版发布后，抓取 GitHub 渲染出的 HTML 逐段核对，发现相当一部分公式在网页上并未按预期显示。**这些问题在本地 Markdown 预览器中全部看不出来**——本地预览器通常直接把 `$...$` 交给 MathJax，而 GitHub 的管线**先做 Markdown 的反斜杠转义与强调解析，再交给 MathJax**，两者的处理顺序不同，结果也就不同。

因此这一类问题只能靠针对 GitHub 管线的检查项守住，不能靠人眼或本地预览。检查项是 [`scripts/check_math.py`](../scripts/check_math.py)，已接入 CI；写作纪律见 [`CLAUDE.md`](../CLAUDE.md) 的「在 Markdown 里写 LaTeX」。

## 检出清单

共 **18 处**源码位置、**20 条**检查项命中。均为渲染缺陷，修复只改写法、不改任何文字内容。

| 类别 | 位置数 | 症状 | 证据 |
|---|---:|---|---|
| **E5** 开定界符 `$` 紧跟中文标点 | 12 | 整段公式**未被识别为数学**，`$F$` 之类原样打印；公式内的 `_` 与 `*` 进一步被当成 Markdown 强调 | 渲染后的 HTML 中这 12 处以字面 `$...$` 出现在正文里，且伴随 `<em>` 标签 |
| **E3** `$$` 与内容同行（在引用块内） | 1 | 行间公式未被识别，渲染为 `$$B_{n+1} \subseteq \big(B_n \setminus \mathrm{Resolved}<em>n\big) \cup \mathrm{New}(d_n \to d</em>{n+1})$$` | 下划线被解析成强调标签，公式彻底破碎 |
| **E1** 公式内 `\%` | 3 | Markdown 先把 `\%` 转义为 `%`，而 `%` 在 TeX 中是注释符，其后内容静默消失 | 渲染后的公式载荷为 `$\lesssim 0.5%$` |
| **E1** 公式内 `\{` `\}` | 1 | 转义后花括号成为 TeX 分组符，**不显示** | 渲染后的公式载荷为 `${正确, 错误}$` |
| **E2** 公式内含 CJK | 2 | MathJax 字体不含 CJK 字形，显示依赖浏览器回退，不可控 | `\text{评审算子}`、`{正确, 错误}` |

其中 E1 的花括号一处与 E2 的一处为同一位置（`$\{正确, 错误\}$` 同时触发三条规则），故位置数为 18 而非 19。

## 修复方式

| 原写法 | 改后 | 理由 |
|---|---|---|
| `空间，$F$ 为` | `空间， $F$ 为` | 中文标点与开定界符之间加半角空格 |
| `> $$公式$$` | `> $$` / `> 公式` / `> $$`，前后各加 `>` 空行 | 定界符独占一行 |
| `$\lesssim 0.5\%$` | `$\lesssim$ 0.5%` | 百分号移出公式 |
| `$\{正确, 错误\}$` | `{正确, 错误}` | 中文不入公式；花括号在 Markdown 中本就是字面量 |
| `$$\text{评审算子}\quad R : D \to 2^{F}, \qquad \text{开发算子}\quad A : D \times 2^{F} \to D$$` | `**评审算子** $R : D \to 2^{F}$，**开发算子** $A : D \times 2^{F} \to D$。` | 中文移出公式 |

**逐字比对确认：修复前后可见文字完全一致**，改动只涉及空白、定界符位置与公式/正文的边界。

## 复现

```bash
python3 scripts/check_math.py          # 现在应输出「检查通过」
git log --oneline -- scripts/check_math.py
```

要复现当初的检出，把上表「改后」一列的写法改回「原写法」再跑一次即可。
